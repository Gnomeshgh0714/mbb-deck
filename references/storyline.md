# Storyline：deck 级叙事契约

本文件管「整副 deck 讲什么、按什么顺序讲」，page-logic.md 管单页。两份契约配合：先在这里定 governing thought 与页序，再逐页走 page-logic -> layout-routing。

本文件只在用户授权内容重组时决定新页序。已有 PPT 或逐页 dummy 的逐页转换任务保留原页序与页面边界，只做标题连读检查，不自行重组。

标注约定：**【硬】**= 违反即 blocker；**【参考】**= 默认起点，可按项目裁剪。

## 1. Governing Thought（先于一切页面设计）【硬】

动手排任何一页之前，先写一句能回答听众核心问题的中心论点。四个质量条件：

- 具体到**可以被反驳**（specific enough to disagree with）
- 有来源证据支撑
- 与某个决策相关
- 短到**能凭记忆复述**

避免空话：「行业正在快速变化」「AI 带来机遇与挑战」都不是 governing thought。GT 定稿后，每一页的 action title 都必须服务它；写完 deck 后回头核对，GT 若无页支撑，改 GT 或补页。

## 2. 横向逻辑 · 连读契约【硬】

把**全部 action title 连读**，必须连成一篇有说服力的短文（不看正文，只读标题）。这是多页 Storyline 的验收标准，也是交付前 Gate 1 的检查项：

- 相邻页不重复同一结论
- 诊断到行动之间无跳跃
- 每个节边界有清晰过渡
- 建议必须回答诊断出的原因
- 附录放细节，而不是藏弱逻辑

结构原则（Pyramid）：**结论先行**。读者只读前 1–2 页就应拿到主结论；先细节后结论的顺序会把主论点淹没。

自检方法（麦肯锡 best practice 同款）：把 deck 缩小到只看得清标题，通读一遍，故事是否成立、能否转述。

## 3. 纵向逻辑【硬】

每页必须含：

1. 答案先行的 action title
2. 一个主导证据结构
3. 解释「证据为何重要」的标注
4. 需要时的来源 / 方法注

执行摘要页的每根支柱必须被后文某页证明；摘要数字与后文对应数字**逐一对账，完全一致**。

## 4. Executive Summary 规范【硬】

可独立阅读，须含：governing thought + 3–5 个支撑洞察 + 2–4 条建议行动（决策导向时）+ 关键量化证据 + 相关的不确定性。**总结结论，而不是总结话题。**

## 5. 页面角色【参考】

每页指派一个角色，写进 page-logic 契约（`page_question` 与之对齐）：

| 角色 | 职责 |
|---|---|
| `orient` | 建立语境 |
| `assert` | 断言洞察 |
| `prove` | 给证据 |
| `compare` | 给对比 |
| `explain` | 给机制 |
| `decide` | 框定选择 |
| `mobilize` | 定行动 |
| `reference` | 方法 / 细节（附录） |

不要在听众需要结论时用 `orient` 页。

## 6. deck 页序配方【参考】

两种默认配方，按内容类型选最简单够用的一种；页序可按项目裁剪，裁剪后连读契约（§2）仍然必须过。

**研究摘要配方（9–11 页）**：

封面 -> 执行摘要 -> 背景 / 拐点 -> 决定性发现 1 -> 决定性发现 2 -> 细分 / 成熟度 / 竞争对比 -> 机制 / 原因 -> 启示 -> 建议行动 -> 路线图 / 决策议程 -> 来源方法

**战略决策配方**：

封面 -> 执行摘要 -> 绩效差距 / 机会 -> 根本原因 -> 战略选择 -> 评估准则 -> 推荐选择 -> 价值论证 -> 实施路线图 -> 风险与缓解 -> 待决事项

## 7. 与其他文件的接口

- 页序确定后，逐页填 [page-logic.md](page-logic.md) 最小内部契约（9 字段）
- 每页证据结构的选择走 [layout-routing.md](layout-routing.md)
- 单页内「论点配承载论证的视觉结构」原则见 [visual-language.md](visual-language.md) §5
