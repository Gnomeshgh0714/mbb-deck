# Visual Language：主动设计而不写死模板

本文件提供生成判断，不定义封闭的 Subtitle 模板库。新的视觉形式只要满足语义、品牌和一致性要求即可使用。

## 1. 不变量与变量

### 不变量

- Action Title、Subtitle、正文和 Footnote 的层级
- 固定两行标题区
- 品牌蓝为品牌主色，灰色保留问题语义
- 同层级平行对象必须同构
- 平行比较区域必须共享行网格，对应模块逐行等高并保持水平对齐
- 箭头与方向必须表达真实逻辑
- 页面必须可读、可编辑、无溢出

### 可变量

- Subtitle 的几何形状、切角、色条、标签和编号
- 页面分栏比例、视觉重心和留白
- 数字强调方式
- 是否使用图标、括号、箭头或暗色面板
- 进入动效的顺序和幅度

## 2. Subtitle 设计语法

Subtitle 可以由以下原语组合，但不要求固定数量或固定样式：

- 实色消息带
- 浅底＋左侧色条
- 编号标签＋标题区
- 切角或方向性标题
- 接收箭头的凹口标题
- 细线、括号或悬浮标签
- 小标签＋主消息的两段式标题

选择时先判断 Subtitle 的逻辑角色：

- 问题或转型前：灰色、稳定、偏封闭
- 总路径或核心行动：品牌蓝、方向清楚、权重最高
- 平行模块：同一组件、严格对称
- 结果或输出：与路径形成接收关系，可使用凹口、括号或结果标签
- 低层级解释：减少实色面积，优先轻量结构

不要让用户选择这些术语。AI 根据内容数量、关系、字数和密度自动路由。

## 3. 控制丰富度

- 一页使用一套主要 Subtitle 视觉语言；问题区和结果区可因语义不同使用角色变体
- 同一层级不得混用圆角卡片、切角标签、胶囊和下划线等多套语言
- 方向性造型只用于存在方向、输入输出或因果关系的场景
- 装饰不能比信息更抢眼；没有逻辑作用时不添加图标、箭头或大色块
- 数字可以高于 18pt，因为数字强调不是 Subtitle 字号；数字与解释文字必须成组
- **强调手法上限**：一页的洞察标注类强调最多使用 **2 种**，防过度装饰。触发规则：

| 触发条件 | 用哪种强调 |
|---|---|
| 单个数字需强调 | 数字徽章（大数字 + 标签成组） |
| 有增减 / 同比 / 环比 | 增减指示（▲▼） |
| 一组并列项需提炼共性 | 结论气泡（洞察短语气泡） |
| 需区分正负 / 前后语义 | 行色带（灰 = 过去 / 负面，主色 = 行动 / 成果） |
| 多栏需归组 | 归组括号 |

图标可用于语义区分场景：当多个平行概念需要快速视觉辨识时，可使用小型图标辅助区分；图标必须满足以下条件才可添加：

- 存在两个及以上平行概念需要区分，且文字标签本身不够直觉
- 图标与概念之间有可理解的语义映射（例如芯片=算力/智能、叶子=可持续/绿色、交叠圆=融合/一体）
- 图标尺寸不超过同层级文字高度，颜色从品牌色系派生，不引入新色相
- 不为单一标签单独添加图标；要么一组平行标签都加，要么都不加
- 平行概念若使用图标，必须分别匹配各自语义，不得机械复用同一图标
- 同组 图标图形可以不同，但应保持线型、尺寸、颜色和复杂度一致
- 若无法找到清晰且不同的语义图标，则宁可不用图标

## 4. 语义色

品牌主色不等于全页单色：

- 灰：问题、现状、约束、基准
- 深蓝：核心主张、主标题框、最高层级
- 主蓝：行动路径、强调、逻辑方向
- 浅蓝：辅助背景、平行模块标题底
- 红、黄、绿等其他语义色暂不主动扩展，除非数据或用户案例明确需要

不能只靠颜色表达意义；同时使用文字标题、位置或形状。

## 5. 逻辑桥梁

**proof-object-first**：每个论点配一个**承载论证的视觉结构**（压力结构图、路径迁移图、演进阶梯、分级矩阵、证据锚点条……），而非卡片 + 图标 + bullet 的堆叠。版式本身要编码论证关系--这与「箭头是逻辑元素、不是装饰」是同一条原则的两种说法。

箭头不是装饰。优先选择能清楚覆盖 source 与 target 的实现：

- 整体路径到结果：在完整路径组与结果区之间放置桥梁，不让箭头看起来只属于最后一栏
- 一对一映射：使用逐项连线或严格行对齐
- 多对一汇聚：使用括号、汇聚箭头或共同容器
- 顺序流程：方向连续，节点间距一致

如果参考页连接器含义不清，先推断并说明；不同解释会改变结论时再询问用户。

## 6. 案例的使用方法

- exemplar 用于学习比例、层级、留白、语义和 taste
- 不复用案例事实，不把案例形状变成强制模板
- 新案例应扩大可用设计空间，而不是覆盖已有语法
- 只有跨页面验证、出现反例并得到用户确认后，候选做法才可晋升为 Foundation 硬规则

当前 `assets/exemplars/` 下的校准范例页只证明以下方向可行：灰色问题块、固定标题区、组合式 Subtitle、路径到结果的箭头和蓝色 number ball。其具体形状仍待继续讨论。

## 7. 数据可视化与图表

- 两个或以上柱形共享尺度并用于定量比较时，保留一条连续的共同基线；基线使用低存在感中性线，不给每根柱子画彼此无关的底线
- 同一张图中的同层级数据标签使用一致字号、字重和数字格式；极小柱无法容纳标签时，把标签移到柱外或使用引导线，不得单独缩小该数字
- 图表重绘前盘点：标题、单位、轴、刻度、年份、系列、图例、可见数据标签、分析标注和来源；不得以“简洁”为由删除解释数据所必需的项目
- 括号、箭头、差值线和 call-out 是论证对象：必须保留 `message`、`anchor` 与 `placement`。样式可升级，不能降级为图下注释或移到与锚点无关的位置
- 严格转换默认保留图表类型、方向、排序和标注构图；确需变换时必须证明所有数据与指向关系语义等价
- viewBox 必须留出标签安全边距：左留 Y 轴标签宽度（约 50–70px），上方留数据标签高度（约 20px），下方留 X 轴标签高度（约 30px）
- 数据标签不得与折线/数据线本体重叠：标签应置于数据点附近（上/下/侧），并与线条保持可读间距，不压线
- 相邻数据点标签不得重叠；当两个数据值接近（Y 坐标差 < 标签高度的 1.5 倍）时，必须采用就近错位策略：一个放上方、一个放下方，或错开水平位置，避免视觉拥挤
- 标签既不可过小（不小于 9pt），也不可为避让而贴边或被裁切；当"清晰可读"与"不拥挤"冲突时，优先保证可读，并通过扩大 viewBox、拉开数据点间距或缩短数字格式（如 6.4% 而非 6.40%）来解决
- 图表区域内的所有文本 bounding box 必须落在 SVG viewBox 内，不得溢出被裁切
- 文字不得与其他文字、数据标签或关键曲线发生非预期重叠；优先采用上下错层、水平错位、引导线和扩大绘图区解决
- 颜色区分必须同时使用位置或形状，不能只靠颜色
- **图表必须被解读**：图表可以成为页面主体，但 Action Title、标注或结论区必须说明它为何重要；2/3 图表 + 1/3 结论栏只是常用结构，不是硬模板
- **填充靠证据组合，不靠拉伸**：内容不足时只能从已有材料中增加结论栏、证据锚点或解读区，不为填满页面发明新内容，也不靠放大字号填空
- 信息较少的小图不强行拉伸填满大容器；保持与信息量相称的紧凑画幅，通过对齐、分组和有意留白建立秩序
- 图表在卡片或容器内应充分利用可用垂直空间：绘图区垂直居中或适当下移，不得出现"上密下空"——即绘图区贴在容器顶部、下方（或四周）留大片空白；在符合可读性与安全边距前提下，AI 可自由决定放大图表尺寸或下移绘图区以消除多余空白。本规则对折线图、柱状图、饼图等所有内嵌图表类型通用


## 8. 模块内垂直分布

- 同一水平带中的不同类型模块也应寻找共同的视觉落点；若图表轴线与相邻案例框、结论区或文字模块的主要底边接近，应优先微调内部高度或留白使其对齐
- 共同底线以正文中的主要轴线或框线为准，不以外层容器、Footnote 或页码为准

- 内容高度不足以填满容器时，先判断已有证据能否组成结论栏、证据锚点或解读条；不能增加时允许保留有意留白或调整构图，不以固定空白率判定失败
- 子区块间距应大于子区块到容器边缘的间距
- 禁止上半紧凑、下半大面积留白
- 判断标准：渲染后垂直中位线以上和以下的内容视觉重量应大致均衡

## 9. Logo、图片与图标资产

- 严格转换中，可见 Logo、图片和图标属于源页面内容；先提取并内嵌到单文件 HTML，不得静默删除或用普通文字替代
- 资产是否承担品牌识别、案例举证、方向提示或装饰作用必须先判断；只有用户明确允许精简时才可删除非关键装饰
- 同一紧密模块内，同一对象只保留一个主标签；不要因为新增行标题或说明文字而重复品牌、公司或产品名称
