# mbb-deck 多平台部署指南

> 目标：让 mbb-deck 不只在 Claude 里可用，也能跑在 OpenAI（ChatGPT / API）、WorkBuddy 及其他模型 / agent 工具上。

## 你手里有什么

| 文件 | 用途 |
|---|---|
| 仓库根目录（`SKILL.md` + `references/` + `scripts/` + `assets/`） | Claude Code 原生 skill（唯一真源，规则改动只改这里） |
| [可移植prompt.md](可移植prompt.md) | 单文件系统提示词，任何平台直接粘贴（由 `scripts/build_portable.py` 生成） |
| [标准调用prompt.md](标准调用prompt.md) | 员工侧调用模板（平台无关，教员工怎么发指令） |
| `assets/exemplars/` | 校准范例（输出质量上限的来源；**公开版仓库不附带范例文件**，私有部署时放入该目录，支持附件的平台务必一并传入） |

**同步纪律**：skill 规则任何改动后，重新执行一条命令，否则可移植版与真源脱钩：

```bash
python3 scripts/build_portable.py docs/可移植prompt.md
```

## 各平台接法

### Claude Code（原生，全功能基准）

- 仓库克隆到项目内 `.claude/skills/mbb-deck/` 直接生效；要全局可用就克隆到 `~/.claude/skills/mbb-deck`
- 完整能力：模式判定（逐页转换 / 内容重组）、脚本机械检查（check_deck.py）、单文件 HTML 交付

### OpenAI

**Custom GPT / ChatGPT Projects（指令栏有约 8000 字符上限）**

1. 指令栏只放 `可移植prompt.md` 的头部：从开头到「范例说明」一节为止（约 2.5KB），即 触发 + 平台能力适配 + 工作流六步 + 判定封闭原则
2. 完整规则作为知识库文件上传：7 个打包源文件（`assets/intake-form.md` + `references/` 下 6 个 md）
3. 有范例 HTML 时（私有部署）一并上传——质量上限靠它
4. 开启 Code Interpreter / 代码执行：恢复脚本机械检查；不开则按头部适配表降级为 HTML-only + 清单自查

**Assistants / Responses API（无长度压力）**

- `system` 直接放完整 `可移植prompt.md`
- 有 file_search / 文件挂载能力时，把范例 HTML 挂上
- 有 code_interpreter 工具时声明启用，恢复 PPTX 与机械检查

### WorkBuddy 及其他 agent 平台（通用接法）

WorkBuddy 等平台的共同形态是「角色设定 / 系统提示词 + 可选知识库 + 可选代码节点」，接法按此通用化：

1. **系统提示词 / 角色设定**：粘贴完整 `可移植prompt.md`（约 44KB，中文平台普遍支持；若有长度限制，按 Custom GPT 的做法拆：头部进指令、7 个规则文件进知识库）
2. **知识库 / 附件**：传入范例 HTML。没有范例时输出质量会落回下限系统水平（规则保正确性，范例保观感）
3. **代码执行节点 / 插件**：接 Python 环境即可恢复机械检查；检查脚本可从 `scripts/` 目录拷走（check_deck.py 是纯标准库，无第三方依赖）
4. **对话式交互**：平台没有结构化点选组件时，skill 会按头部适配表自动降级为文字选项提问，无需改造

### 未来兼容：开放 Agent Skills 格式

SKILL.md 目录结构已是行业开放规范（agentskills.io 一类）的通用形态。若某工具声明支持「Agent Skills / SKILL.md 目录」，直接整个目录拷入即可，无需可移植版。

## 能力降级对照表

| 功能 | Claude Code | API / agent 平台 | 纯聊天（无代码无附件） |
|---|---|---|---|
| HTML 交付 | ✓ 直接写文件 | ✓ | ✓（代码块输出） |
| PPTX 交付 | ✓ | 需代码执行 | ✗ |
| 机械检查（溢出 / 重叠 / 数据读回） | ✓ 脚本执行 | 需代码执行 | 降级为清单自查 + 披露 |
| 触发点选表单 | ✓ | 看平台组件 | 文字选项提问 |
| 范例校准 | ✓ 读文件 | 需知识库 / 附件 | 需粘贴进上下文 |
| 开工简报 | ✓ | ✓ | ✓ |

## 员工侧统一话术（所有平台通用）

员工不需要知道自己在用哪个平台的后端。调用格式统一用 [标准调用prompt.md](标准调用prompt.md) 里的板块式模板；该模板在 Claude（说「用 mbb-deck skill」）和任何已部署可移植 prompt 的平台（直接贴内容）下行为一致。

## 已知限制（如实告知用户）

- 无代码执行的平台拿不到 PPTX，也拿不到脚本级机械检查——交付说明里会带「机械检查：未执行」的披露，人工验收时按 QA Gates 清单过一遍
- 无范例校准的平台，观感会明显低于带范例的产出（范例不随提示词打包是体积所迫）
- 图表数据从素材到成片的转录核对在有脚本时是机械读回，无脚本时靠自查，出错概率高于带脚本端
